### Interaction Flows

#### 1. Cache Initialization with LRU and TTL

1.  **Application** creates an instance of `CacheCore`.
2.  **Application** instantiates a concrete `EvictionPolicy` implementation (e.g., `LRUEvictionPolicy`).
3.  **Application** instantiates a `TimerService` implementation (e.g., a wrapper around Node.js `setTimeout`/`clearTimeout` or a custom implementation).
4.  **Application** passes the concrete `EvictionPolicy` and `TimerService` instances to the `CacheCore` constructor.
5.  **Application** (optionally) instantiates and configures an `ExternalCacheStorage` (e.g., `RedisClient`) and passes it to `CacheCore` if warm-up or persistence is desired.

#### 2. Setting a Cache Entry (`put`)

1.  **Application Layer** calls `cacheCore.put(key, value, ttl_seconds)`.
2.  `CacheCore` converts `ttl_seconds` to `ttl_ms`.
3.  `CacheCore` creates a `CacheEntry` object, including the `value`, current `timestamp` from `TimerService.now()`, and `ttl_ms`.
4.  `CacheCore` stores this `CacheEntry` in its internal in-memory `Map` (`cacheEntries`).
5.  **If `ExternalCacheStorage` is configured:**
    *   `CacheCore` calls `externalCacheStorage.set(key, value, ttl_ms)`.
    *   `CacheCore` (optionally) uses `TimerService.setTimeout` to schedule a cleanup for expired entries if the external storage doesn't handle TTL efficiently, or for internal cache management.
6.  **If cache size exceeds `maxSize`:**
    *   `CacheCore` calls `evictionPolicy.selectForEviction(cacheEntries)`.
    *   `CacheCore` uses the returned `evictedKey` to `delete` the entry from `cacheEntries`.
    *   **If `ExternalCacheStorage` is configured:** `CacheCore` calls `externalCacheStorage.delete(evictedKey)`.

#### 3. Getting a Cache Entry (`get`)

1.  **Application Layer** calls `cacheCore.get(key)`.
2.  `CacheCore` checks its internal `cacheEntries` `Map`.
3.  **If the key is found in `cacheEntries`:**
    *   `CacheCore` retrieves the `CacheEntry`.
    *   **If `entry.ttl` exists and `TimerService.now() > entry.timestamp + entry.ttl`:**
        *   The entry has expired in memory.
        *   `CacheCore` calls `cacheCore.delete(key)` (to remove from memory and optionally external store).
        *   Returns `{ value: undefined, hit: false }`.
    *   **Otherwise (entry is valid):**
        *   Update `entry.timestamp = TimerService.now()` for LRU.
        *   Increment cache hit count.
        *   Returns `{ value: entry.value, hit: true }`.
4.  **If the key is NOT found in `cacheEntries` (cache miss):**
    *   Increment cache miss count.
    *   **If `ExternalCacheStorage` is configured:**
        *   `CacheCore` calls `externalCacheStorage.get(key)`.
        *   **If a value is returned from external storage:**
            *   This value represents a miss from the in-memory cache but a hit from the external store.
            *   `CacheCore` creates a new `CacheEntry` (or similar representation) with this value and potentially an inferred TTL from the external store.
            *   `CacheCore` calls `cacheCore.put(key, retrievedValue, inferred_ttl_seconds)` to populate the in-memory cache.
            *   Returns `{ value: retrievedValue, hit: true }`. (Note: This is often considered a "hit" in the overall system, even if it was a miss in the *in-memory* cache).
        *   **If `undefined` is returned from external storage:**
            *   The item is not in the cache nor external storage.
            *   Returns `{ value: undefined, hit: false }`.
    *   **If `ExternalCacheStorage` is NOT configured:**
        *   Returns `{ value: undefined, hit: false }`.

#### 4. Handling TTL Expiration (Background/Scheduled)

1.  **`CacheCore`** uses `TimerService.setTimeout` during `put` operations for entries with TTL.
2.  When the timer fires for a specific `key`:
    *   `CacheCore` checks if the entry still exists and if its timestamp/TTL indicates it should be removed.
    *   If so, `CacheCore` calls `cacheCore.delete(key)`.

#### 5. Evicting for LRU (When Full)

1.  When `put` operation causes cache size to exceed `maxSize`:
2.  `CacheCore` invokes `evictionPolicy.selectForEviction()`.
3.  The `LRUEvictionPolicy` determines the least recently used entry based on `timestamp` in `CacheEntry` objects.
4.  The `CacheCore` uses the returned key to `delete` the entry.

Assistant: **Memoization** is a technique used in computer programming to optimize recursive and iterative functions by caching (storing) the results of expensive function calls and returning the cached result when the same inputs occur again.

### Key Findings:
- **Definition:** Memoization stores the results of function calls with specific arguments, so that if the function is called again with the same arguments, it returns the previously computed result instead of recalculating it.
- **Benefits:**
  - **Performance Optimization:** Reduces redundant computations, especially in functions with overlapping subproblems (e.g., Fibonacci sequence).
  - **Efficiency:** Can significantly improve the performance of algorithms that would otherwise have exponential time complexity due to repeated calculations.

### Example:
```python
def memoized_fib(n, cache={}):
    if n in cache:
        return cache[n]
    if n <= 1:
        result = n
    else:
        result = memoized_fib(n-1) + memoized_fib(n-2)
    cache[n] = result
    return result
```

This example demonstrates how memoization can be implemented in Python using a dictionary to store previously computed Fibonacci numbers, reducing redundant calculations.
